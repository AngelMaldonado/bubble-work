## Cómo escribir markdown aquí

- **Idioma:** escribe documentos, comentarios y artefactos en el idioma del equipo (en este departamento, español), aunque las tools y sus parámetros estén en inglés.
- **Forma sugerida de un hilo** (no obligatoria; escribe la forma que tenga el trabajo): por qué existe, qué es cierto cuando esté hecho, el siguiente paso concreto, los pasos como casillas `- [ ]`, y la evidencia enlazada.
- Escribe cada párrafo como una sola línea lógica: no hagas hard-wrap a 72/80 columnas. Deja que el navegador ajuste el texto al ancho disponible. Separa párrafos con una línea vacía.
- No añadas `<br>` ni dos espacios al final de una línea para partir frases antes de tiempo. Úsalos sólo cuando el salto tenga sentido real (una dirección, un poema), nunca como ajuste de pantalla.
- Usa títulos, listas y tablas por su significado, no para maquetar columnas. No metas espacios ni tablas para forzar un ancho.
- **Se renderiza:** títulos, listas, tablas, bloques de código, diagramas mermaid (bloque ```` ```mermaid ````), casillas, enlaces e imágenes de `assets/` (cítalas como `assets/<nombre>`).
- **El HTML no se renderiza:** se muestra escapado, como texto. No escribas HTML ni CSS para lograr nada.
- Las casillas son markdown real (`- [ ]` / `- [x]`), con texto verificable; no inventes actividad ni marques hechos que no se cumplieron.
- Énfasis: `**negrita**`, `*cursiva*` y `++subrayado++` (extensión de Bubble). Con moderación, y nunca para simular títulos.
